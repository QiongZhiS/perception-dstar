## 一、预注册设计（判据先于最终运行冻结，docs/63 纪律）

### 1.1 缘起与目标（冻结）

docs/243 判明：能量分档的"涌现能力"迁移、"判别分辨率"不迁移（部分迁移）——toy 调的
粗分档（ENERGY_BINS [150,450,2000,3000] / UPPER_BINS [420,1000,1800,2800]）在 160×120
真实像素流上把 9 个场景压成 2 个基签名 (1,0)/(0,0)，8 处切换仅 2 处被新条目编码。
本实验的目标：**从真实视频统计重定 c0/c1 分档边界**，使不同场景尽量落在不同档，复测
桥对应率；同时用**留出视频**检验分档泛化，防止"分档调在校准集上"的二次校准循环。

### 1.2 校准 / 测试分离（防循环，冻结）

- **校准集（5 视频）**：flamingo / surf / bear / camel / dog（R1 流中前 5 段，367 帧）。
- **留出集（4 视频）**：blackswan / car-turn / motorbike / soccerball（221 帧）。
- **分档只在校准集上统计**，然后应用到完整 9 视频流（R0 与 R1 都用新分档）；
  留出视频在分档估计中**零贡献**——留出集的切换对应率是泛化检验的唯一证据。
- **防循环声明**：若校准集切换对应率高而留出集不过线 → 如实报告"分档过拟合校准集"
  （verdict=RECAL_PARTIAL）；不允许用留出集结果回调分档。

### 1.3 数据与预处理（冻结，沿用 docs/243）

- 数据：vision/out/davis/<video>/ 的 JPEG 帧（flamingo 80 / surf 55 / bear 82 / camel 90 /
  dog 60 / blackswan 50 / car-turn 80 / motorbike 43 / soccerball 48，共 588 帧）。
- 预处理固定流水线：`cv2.imread(IMREAD_GRAYSCALE)` → `cv2.resize(160×120, INTER_AREA)`
  → uint8（能量分档是 160×120 工作点的分辨率归一化量，docs/243 §1.1 冻结理由）。
- 无注入、无 jitter、无 RNG：真实像素流确定性；统计外壳为窗口级（docs/243 §1.5 同款）。

### 1.4 分档法（预注册，冻结）

**校准统计量**：校准集拼接流（= R1 流前 367 帧，与完整流的前 37 个窗口逐帧同构——
回路在两条流上都在 flamingo 首帧冷启动）上，每窗口事件量 E = 窗口事件像素总数
（loop.energy_trace）与上区事件量 U = y<68 上组事件像素总数（loop.up_trace）。
事件检测（预测/阈值）与分档无关——用默认 LOOP_CFG 跑校准 pass 得到的 E/U 与测试
pass 完全相同（bins 只改签名档位，不改事件掩码）。

**分档规则（等频分位数，标签无关）**：
- c0 新边界（energy_bins）= E 的 20/40/60/80 分位数，四舍五入到 1 位小数，去重后
  严格递增（保持 5 档签名空间形状，与 toy 相同；去重后档数减少 = 数据本身性质，
  如实报告，无人工回退）。
- c1 新边界（bbox_bins）= U 的 20/40/60/80 分位数，同样取整/去重。
- **标签无关**：不使用任何视频身份/场景标签；窗口按校准集全体混合（pooled）统计，
  每个窗口等权。

**禁止条款（预注册声明）**：**逐场景归一化（把每个场景的能量按其自身范围缩放/定档）
不得作为主方案**——归一化会把场景边界信息泄漏进签名，使切换编码平凡化（分档"知道"
场景边界 = 校准循环的另一种形态）。本实验分档完全不用场景身份；也不设"看过结果后
按诊断回调分档"的任何轮次（单次确定性校准 pass，docs/235 的 8 轮校准更严格）。

### 1.5 级别与流（冻结，沿用 docs/243）

| 级 | 代码 | 名称 | 流构造 | 测什么 |
|---|---|---|---|---|
| **R0** | 30 | single_video_loop | flamingo 80 帧 × 5 = **400 帧**（循环 = 半真实妥协） | 重校准不破坏单场景结构涌现/稳定 |
| **R1** | 31 | concat_scenes | 9 视频按序拼接 = **588 帧**；8 处切换（帧 80/135/217/307/367/417/497/540） | 重校准后桥对应率（完整流 + 校准/留出分列） |

R1 视频跨度（0 基帧区间）：flamingo [0,80)、surf [80,135)、bear [135,217)、camel
[217,307)、dog [307,367)、blackswan [367,417)、car-turn [417,497)、motorbike [497,540)、
soccerball [540,588)。

**桥度量定义（沿用 docs/243 §1.4，逐字）**：切换 i（i=1..8，S_i = 下一视频起始帧）
**被编码** ⇔ ≥1 个新条目创建窗口 w 满足 `S_i ≤ w×10 < S_i + len(下一视频)`；
`bridge_corr_switch = 被编码切换数 / 8`；`bridge_corr_video = 跨度内有条目的视频数 / 9`；
`spurious_rate = 不落在任何视频跨度内的条目数 / max(1,SC1)`。
**切换分列（本轮新增，预注册）**：
- **校准切换** = 切换到 surf/bear/camel/dog 的 4 处（视频 1..4），`calib_switch` =
  被编码数 / 4；
- **留出切换** = 切换到 blackswan/car-turn/motorbike/soccerball 的 4 处（视频 5..8），
  `holdout_switch` = 被编码数 / 4。

### 1.6 判据（预注册，先于最终运行冻结；不得在看过结果后修改）

1. **BRIDGE_FIX**：完整 9 视频流（新分档）`bridge_corr_switch ≥ 0.5`（docs/243 为 0.25）。
2. **HELD_OUT**：`holdout_switch ≥ 0.5`（留出视频切换对应率——只有留出集过线才算
   泛化；`calib_switch` 分开报告，不进判据；若留出集不过线 → 如实报告"分档过拟合
   校准集"）。
3. **STRUCT_STILL**：`SC2 > 0` 且 `churn ≤ 0.5`，**R0 与 R1 均要求**（与 docs/243
   STRUCT_EMERGES 同口径：重校准不破坏结构涌现；churn ≤ 0.5 沿用 docs/243 放宽值）。
4. **STABLE_STILL**：`MAE 末/首四分之一窗口均值比 ≤ 1.5`，**R0 与 R1 均要求**
   （与 docs/243 REAL_STABLE 同口径：重校准不破坏稳定性）。

**判定（冻结）**：全过 = **RECAL_PASS**；判据 3 或 4 失败（结构/稳定被破坏）=
**RECAL_FAIL**；判据 3/4 过但 1 或 2 不过 = **RECAL_PARTIAL**——其中 BRIDGE_FIX 过
而 HELD_OUT 不过 → 注明"分档过拟合校准集"；BRIDGE_FIX 本身不过 → 注明"重校准未修复
桥（数字见报告）"；判据无法计算（数据缺失等）= **PARTIAL**（照实）。

**不重测项（预注册声明）**：STATE_PERSIST 不重测——分档只改签名档位配置值，状态
save/load 机制未动（docs/243 已 6/6 全等）；本实验只关心分档变化引起的判别/结构/稳定
行为差异。

### 1.7 诊断项（不进判据）

- **旧分档 R1 回归**：同一脚本用旧 bins 重跑 R1，验证与 docs/243 数字一致

- **逐场景签名**：新分档下每视频窗口 (c0,c1) 众数签名与唯一签名数（分档分辨率诊断）。
- **校准集能量分布**：E/U 的 min/median/max 与窗口数。

### 1.8 统计与安全纪律（冻结，docs/243 同款）

- 固定确定性流；窗口级统计（mean±SD（ddof=1）+ bootstrap 95% CI，2000 次，种子

  bins 新旧 / 逐级 per_level / 桥明细 / per_scene_sig / 判据逐项 / verdict / timing）。
- 计算预算 ≤ 60 分钟（预期 ≤ 10 秒：R0+R1+旧档回归+校准 ≈ 2000 帧）。
- 安全纪律：stdout 只输出 ASCII 标签 + 每行一个数字的 R_RRC_* 摘要块；运行经

## 五、诚实边界

1. **判定纪律**：§1.6 判据在最终运行前冻结（写入 docs/244 先于任何运行）；计时运行与
   最终运行之间只修一处实现 bug（R0 无 bridge 键的摘要引用，最终运行前修复，判据/
   机制/参数未动）；两运行数字逐位一致（确定性流）。
2. **防循环合规**：分档只在校准集（5 视频）统计；留出集（4 视频）在分档估计中零贡献；
   单次确定性校准 pass，无任何"看过结果后回调分档"的轮次；留出切换对应率 0.25 如实
   报告。防循环结构执行正确——失败是分档法本身的问题，不是流程泄漏。
3. **本失败的具体机制（诚实判读）**：等频分位数把边界放在"窗口质量的 20/40/60/80
   分位"，而校准集内**场景间能量中位数差与场景内窗口间方差同量级**（如 flamingo 8
   窗口 6 个唯一签名）→ 边界切穿场景内部 → 同一场景窗口频繁跨档 → 一致性条件失守 →
   结构坍缩。桥仍 0.25，但**原因与 docs/243 不同**：不是"场景坍缩进共享基签名"
   （判别分辨率不足），而是"签名在场景内不稳定，条目几乎不形成"（一致性被破坏）。
   这是对**预注册的等频分位数法**的具体证伪，**不是**对"真实分档可行"的证伪。
4. **替代方案边界（诚实声明）**：一个不同的、仍标签无关的分档法（更少档位、或边界
   选择以保场景内一致性为目标，如按能量分布的多峰/间隙定档）可能修复桥——但任何新
   选择必须作为新实验（docs/245+）预注册后运行，本实验不允许用结果回调分档（否则
   构成二次校准循环）。
5. **逐场景归一化的禁用（预注册 §1.4 声明，执行确认）**：主方案完全未用任何场景身份/
   逐场景统计；逐场景归一化（会平凡化切换编码）未使用、未作为诊断对照（本实验无需
   诊断对照——主方案已失败）。
6. **R0 判据口径**：STRUCT_STILL 对 R0 与 R1 均要求（预注册 §1.6，同 docs/243

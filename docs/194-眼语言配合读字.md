## 〇、一句话

> **人读字不是 OCR（单遍、无上下文、无核对），是预测-核对闭环：眼睛给弱似然（模糊字形
> 签名），语言给强先验（上下文候选集），后验=先验×似然，视觉核对纠正（docs/125 预期被
> 世界纠正）。最小实验验证：语言缩小候选使模糊字形识别率 6 倍（无上下文 1/15 → 有上下文
> 6/15）；幻觉纪律 15/15——语言给错候选时视觉核对的距离检验全拒识，先验从不直接写状态
> （docs/123：幻觉=先验冒充后验的反面）。语言部分完成（language_prior 通道 LLM 优先/
> 规则回退 + 2D 签名序列读字）：三条件合验——视觉弱时补（6 倍）、视觉强时不扰（0.77）、
> 给错时拒（15/15）。**配合 ≠ 幻觉：语言引导+验证，不冒充视觉证据。**

## 一、机制：预测编码闭环读字

```
眼睛（似然，弱）：扫视定位 + 明度笔画 → 模糊字形签名（"像个 B 或 8"）
语言（先验，强）：上下文预测 → "字母表里 AB_ 后最可能是 C"（docs/107 猜中预期）
结合（后验）：后验 = 先验 × 似然 → "是 C"
反馈（docs/125）：下一格视觉证据核对 → 对了继续，错了被世界纠正
```

- 视觉线索不够时（潦草/缺笔画/遮挡/倾斜），上下文把候选从 26 个缩到几个（docs/193
  字形签名区分度弱没关系，语言补上）；
- 这是 docs/186 §五"三模态竞争"在文字上的第一个具体实现（视觉事件得分 vs 语义落空
  得分）。

## 二、实验（vision/eye_language.py）

- 视觉侧：渲染字母（blur 2-4 / shear 0.3-0.7 / noise 12-30 = 弱视觉），列直方图签名 +
  A-Z 小字库；
- 语言侧：规则化上下文候选集（"AB_" 后 {C,G,O}，docs/107 猜中预期的规则版）；
- 识别 = 签名在候选集内选最近；对照 = 无上下文（全 26）；
- 幻觉纪律：语言给错候选（不含真值）→ 视觉核对应拒识（距离检验：候选距离显著大于
  正常候选则拒绝）。

## 三、结果

| 判据 | 结果 |
|---|---|
| P1 语言缩小候选 | **无上下文 1/15 → 有上下文 6/15（6 倍）** PASS |
| P2 幻觉纪律（拒识） | **15/15 拒识** PASS |

- 模糊字形（blur≥3）无上下文几乎全错（乱猜 J/Y/A）；给上下文候选集后 40% 正确；
- 语言给错候选时，距离检验全部触发拒识——**没有一次误信先验**。

## 四、判读

1. **预测编码闭环在文字上跑通**（docs/125 原样应用）：眼给弱似然、语言给强先验、后验=
   先验×似然、视觉核对纠正——这是"训练=闭环"在识别任务上的体现；
2. **语言先验的有效性**：候选从 26→3，识别率 6 倍——人读潦草字靠上下文的机制被复现；
3. **幻觉防线的形式化**：距离检验 = "先验候选与视觉证据不匹配就拒识"——docs/123
   "幻觉=先验冒充后验"的反面被形式化并实测（15/15 拒识）；
4. **与 OCR 的本质区别**：OCR 是单遍开环（一次识别、无上下文、无核对）；我们是预测-
   核对闭环（先验缩小候选+视觉验证）——docs/125"训练=闭环 vs 推理=开环"在文字识别上
   的体现。OCR 是"嘴"（输出语义的工具），不是"眼+脑"（闭环识别机制）。

## 五、诚实边界

1. 语言先验是**规则化候选集**，不是真正的 LLM 上下文——验证的是"先验缩小候选"的机制，
   不是语言模型的上下文建模（接 LLM 是 docs/148 嘴通道的事，可选下一步）；
2. 识别率 6/15 不算高——列直方图签名弱（docs/193 已证），配合 2D 网格签名可再升；
   本实验的价值在机制验证（闭环有效 + 拒识有效），不在识别率绝对值；
3. 字库 26 字母、单字符——多字符序列（上下文更强的真实场景）未测；
4. 距离检验阈值（1.5× 或 >8.0）是手调——真实拒识阈值需校准。

## 六、语言部分完成（2026-08-27 下午）：语言先验通道 + 序列读字

**语言先验通道**（`vision/language_prior.py`）：docs/148 嘴的上行轨（输入侧预测，与
mouth_llm 输出侧分离）——LLM 优先（DEEPSEEK_API_KEY → deepseek-chat 预测"AB_" 后字符）、
无 key 优雅回退规则候选集（docs/56 心不依赖嘴）。铁律不变：只预测不写状态（docs/123）。

**序列读字**（`vision/sequence_read.py`）：整词逐字符读，语言先验=已读前缀。2D 网格签名
（列直方图升级）使视觉似然大增：无语言 **23/30（0.77）**（vs 列直方图的 0/30）。

**三条件合验（语言先验的完整行为谱）**：
| 条件 | 实验 | 结果 |
|---|---|---|
| ① 视觉弱时语言补 | eye_language（列直方图） | 1/15 → 6/15（6 倍） |
| ② 视觉强时语言不干扰 | sequence_read（2D 签名） | 有语言=无语言=0.77（不帮倒忙） |
| ③ 语言给错时拒识 | eye_language 距离检验 | 15/15（docs/123 不冒充） |

**结论**：语言先验的正确角色 = **视觉弱时补、视觉强时不扰、给错时拒**——预测编码闭环的
完整行为谱，三个条件全部实测。诚实边界：无 key 时规则回退只覆盖 1/3 位置（真语言威力
需 DEEPSEEK_API_KEY，代码已就绪、LLM 路径未跑）。

### 六.5 真 LLM 验证（2026-08-27 下午，DEEPSEEK_API_KEY 配齐）

LLM 分支工作（4/4 次 LLM、0 回退），预测质量显著高于规则：`CA_`→N 0.47（CAN，规则表
没有）、`TH_`→E 0.45（THE）、`XQ_`→E 0.44（无意义前缀回落到字母频率，合理）。

序列读字 + LLM：
| 视觉强度 | 无语言 | 有语言(LLM) | 提升 |
|---|---|---|---|
| 强（blur=1.5） | 0.77 | **0.83** | +6.7%（补边角） |
| **弱（blur=2.5）** | 0.37 | **0.67** | **+30%（补主力）** |

- 语言命中 17 位（规则回退只 10 位）——LLM 上下文覆盖面宽；
- 三条件①（视觉弱语言补）在真 LLM + 2D 签名下复验：0.37→0.67；
- key 用法：环境变量 `DEEPSEEK_API_KEY`（绝不落盘，docs/56 纪律）；无 key 优雅回退。

**语言部分完成**：LLM 优先/规则回退双路径、视觉强不扰/弱补/错拒三条件全验、key 配齐
LLM 实测。下一步是把它接回扫视链路（屏幕感知完整闭环）。

### 六.6 屏幕感知完整链（原型，收尾记录）

`vision/screen_read.py`：静态画面 → 扫视标记区域 → deskew（PCA 主轴，仅 >8° 转）→
字符切分（列密度间隙）→ 2D 签名 + LLM 语言识别（全库 vs 候选取更近——docs/125 后验=
先验×似然，视觉强时语言不扰）。

结果（blur=1.5/noise=8，正排版）：STORE 0.80、TRACK 0.80、CHAIN 0.40、CATCH 0。
- **切分：STORE/TRACK/CHAIN 5/5，CATCH 崩（1 个）**——列密度间隙对 C-A 笔画粘连+噪声
  脆弱；真实屏幕需连通域分析（工程化，非路线问题）；
- **识别：无语言时 4/5 最近正确（docs 诊断）**——2D 签名 + 语言取更近的机制对；
- **语言命中 2-4 位**——LLM 上下文正常参与。

**状态**：原型可跑、机制完整（扫视/切分/识别/语言四环节都单独验证过），稳定性差——
切分启发式是瓶颈。语言识别部分本身（本文件主目标）已完整完成；屏幕感知链记为
"原型演示 + 切分工程化待做"。

### 六.7 先验切分（2026-08-27 晚，切分瓶颈的修复）

粘连字符（C-A 无间隙）时纯后验（列密度间隙）切分崩：4 块（块含 C+A），识别 0/5。
**先验切分**（`vision/prior_segment.py`）：语言先验（词长 5）+ 视觉签名裁决切缝——
粘连块（宽 94≈2 字符）先验说"切 2"，块内扫切缝取"两侧签名距离和最小"（视觉确认）：
恢复 5 块，识别 **5/5**。

**意义**：人切分是先验驱动的实证（docs/194 六.6 结论）——词汇先验（"这词 5 个字母"）
+ 视觉裁决（切缝让两侧都像字符），不是后验扫描间隙。纯后验崩（0/5）→ 先验切分救回
（5/5）——docs/125"先验缩小候选、视觉确认"在切分上的体现。**切分正确形态 = 语言先验
（词长/词汇）+ 颜色分割（docs/192 文字色连通域）+ 视觉签名裁决**。

### 六.8 颜色×先验切分（2026-08-27 晚，docs/192 颜色=区分主轴在切分上的实证）

场景：同亮度蓝灰底 + 黄字（明度完全失效——字与底同为 178，只有色相可分）：

| 切分依据 | 块数 | 识别 |
|---|---|---|
| 明度阈值（>100） | 1 块（全画面） | **0/5**（I）——明度盲 |
| 颜色掩码（H 15-45 黄 + 连通域面积过滤） | **5 块** | **5/5**（CATCH）——色相可分 |

**实证**：同亮度下明度盲、颜色可分——颜色分割是明度失效场景的唯一有效切分依据
（docs/192 §二：颜色=区分主轴、明度=遮挡的分工在切分上的体现）。实现要点：
颜色掩码后按连通域面积过滤（保留文字字符大块、剔除背景同色碎片），不用最大连通域
（文字字符间有间隙，不是一个连通体）。粘连+先验组合在 prior_segment 单独验证
（0/5→5/5）。

### 六.9 屏幕感知完整链（鲁棒版，2026-08-27 晚，收尾）

`vision/screen_read_full.py`：三段合一——颜色掩码（同亮度底分离，docs/192）+ 先验
切分（粘连恢复，docs/194 六.7）+ 2D 签名 + LLM 语言候选（docs/125 后验=先验×似然）。
三困难条件叠加（同亮度蓝灰底 + C-A 粘连 + blur 2.0/noise 10 字形）：

| 词 | 后验切分 | 先验切分 | 识别 | 判据 |
|---|---|---|---|---|
| CATCH | 4 块（粘连） | 5 块（恢复） | **5/5** | PASS |
| STORE | 4 块（粘连） | 5 块 | **5/5** | PASS |
| CHAIN | 4 块（粘连） | 5 块 | **5/5** | PASS |

**收尾结论**：屏幕感知完整链在全部困难条件下工作——颜色分离（明度失效）→ 后验崩

docs/194 三条件③）。**语言识别部分（docs/194 主目标）+ 屏幕感知链（颜色×扫视×先验×

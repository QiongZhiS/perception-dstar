## 一、颜色多通道转导（vision/color_transduction.py）

**实现**：色相（H）sin/cos 环形编码（避免 0-180 断裂）+ 明度（V）双通道并行转导。
色相通道：双值背景 EWMA → 时间差分 → pending → 事件（颜色事件 = 色相落空）；
明度通道：复用 Transduction2D（V 当灰度）。可选通道间侧抑制（lateral）。

**机制验证（合成场景）**：
| 测试 | 结果 | 含义 |
|---|---|---|
| 静止彩色（蓝底+青块，30 帧） | **0 色相事件** | 静止颜色被适应——颜色也是落空载体（docs/187 同构） |
| 颜色切换（t=30 方块变红） | **1764 事件爆发** | 颜色变化 = 颜色落空 = 事件 |
| 切换后（新色稳定） | 92.8/帧 → 回落 | 新颜色被适应（颜色恒常的信息层版） |

## 二、颜色辅助锁定（"找绿的车"）

**实现**：任务层给颜色描述（色相 100-140 + 饱和度 <60 = 车的低饱和绿）→ 锁"目标色相
像素的颜色事件"质心 → 维持。

**结果（car-turn）**：锁定成功，维持率 **0.175** < 灰度基线 0.412。
- f1 锁定误差 154px（背景低饱和绿事件质心主导）→ 后段收敛 16px（车靠近、占比升）；
- 背景同色诊断：f5 时绿色像素 14 万但仅 6% 在车内（树/草/地面也是绿）。

**结论（诚实）**：
1. **颜色是感知层内部"可分"的第一个维度**（docs/192 §一实测：车 53% 覆盖率 vs 背景
   3% 误纳）——对比灰度七维全不可分（docs/188），这是质的突破；
2. **但"颜色描述锁定"受"描述不唯一"限制**：任务层说"找绿的车"，背景也有绿 → 锁定
   到背景。需要**颜色 + 空间锚**（"那辆绿车"的位置）或**更特异描述**（颜色+形状+尺寸），
   纯描述锁定（无论灰度还是颜色）都受此限（docs/191 同结论）。

## 三、主动采样读静态字幕（vision/saccade_read.py）

**场景修正的落地**（docs/192 §三：静止≠盲，扫视制造落空）：
1. **被动整帧转导：10 帧 0 事件**——复现"事件驱动对静态字幕盲"（C1 局限在屏幕场景）；
2. **主动扫视**：窗口（64px，2° 类比）依次扫过静态字幕 → 文字边缘进入/离开窗口 =
   窗口内容差分 = 主动制造的落空 → 累计事件标记文字列；
3. **结果：precision 0.837 / recall 0.862**——扫视从静止画面读出文字区域（判据 >0.5
   大幅兑现）。

**意义**：人读不动字幕靠扫视（docs/190 想看什么看见什么；docs/187 欣赏=微扫视保持落空
同构），机器用扫视窗口同样能读——"屏幕静态感知"的机制落地；docs/133 实验③（中央凹+
扫视）从"可选"变成"已验证的最小版"。

## 四、对路线的含义

1. **颜色 = 可分维度，但需要"颜色+空间"复合描述**：纯颜色描述锁定受背景同色限制；
   复合（颜色+位置锚+形状）是"任务层外赋"的下一步（docs/192 §四修正的工程化）；
2. **扫视读静态 = 屏幕感知的能力基础**：被动事件流管"世界在动"（自然场景），扫视管
   "静态信息的读取"（屏幕场景）——两个模式互补（docs/192 §三）；
3. **颜色转导可并入管线**：色相事件流 + 明度事件流 = 更丰富的事件信号（docs/133
   腹侧通路：颜色→识别、明度→遮挡，分层正确）。

## 五、下一步（按价值）

1. **颜色+空间复合锁定**：任务层"找那辆绿车"（颜色描述 + 初始位置锚）→ 颜色通道 +
   空间约束联合锁定——验证是否超过灰度 0.412；
2. **扫视读字幕接语义**：扫视标记的文字区域 → 态势输出（"文字在 (x1,x2)"）→ 接 OCR
   或逐字采样读取（docs/160 态势接口的屏幕版）；
3. **颜色通道并入真实管线**：DAVIS 多视频验证色相事件流对检出/误报的影响。

## 〇、一句话

> **能效的理论最低 = 事件数 × 单位成本 + 目标确认成本（O(事件+K)），静态段趋近 0。
> 三条线：物理下限（事件数 = 场景变化量，不可突破）、硬件下限（事件相机把转导放
> 进传感器电路）、软件下限（转导层从 O(W×H) 降到 O(变化区)，还剩 20-30× 空间）。
> 工程方向：先追软件下限（转导稀疏化），把"事件数"当能效旋钮（自适应 θ），用
> "多目标线性代价"兑现"机器看更多"——停在物理下限，不碰 SNN 硬件竞赛主场。**

## 二、理论最低：三条线

### 物理下限（不可突破，别在这花时间）

```
能效下限 = 事件数 × 单位成本 + 目标确认成本（O(事件+K)），静态段 → 0
```

- **事件数 = 场景变化量本身**——这是信息论给出的：不变化的像素没有信息，没有信息
  就不该消耗算力。这是物理下限，任何算法都突破不了。
- 工程含义：别试图"算得比事件更少"——那是违反信息论的死路。

### 硬件下限（事件相机，突破软件路径的钥匙）

- 转导层（对数/差分/累积）在真事件相机里由**传感器模拟电路**完成（微瓦级固定功耗），
  不占算法能耗。
- 硬件极限 = 传感器功耗（固定）+ O(事件数) 算法——静态场景算法层趋近 0。
- 工程含义：软件路径能到"O(变化区)"，硬件路径能彻底消除转导——但需硬件
  （Prophesee/DAVIS 等）。

### 软件下限（当前能摸到的天花板）

```
转导层从 O(W×H) → O(变化区)：帧间差分掩码，只在变化处转导
```

- 现状：每帧全帧对数+双 EWMA+累积 = O(W×H)。
- 优化：帧间差分 → 运动掩码 → 静态段转导 O(W×H)→0，动态段只在变化区算。
- **软件极限 ≈ C 形态的 3-5% 再砍掉转导层，静态段趋近 0**——还剩 20-30× 空间，
  全在转导层。

## 三、工程方向（理论最低给实际领域指的路）

### 方向 1：转导层稀疏化（软件极限，最现实）
- 纯算法（帧差分掩码），不换硬件，静态段转导 → 0。
- 这是"低能耗持续视觉"从论文数字变成真实系统能效的关键一步。
- **实现：`vision/transduction_sparse.py`（2026-08-28）**——脚本已实现并通过安全运行
  验证（exit=0，输出落盘 `logs/transduction_sparse_out.txt`）；实测数字待人工回填。

### 方向 2：多目标/多焦点的代价线性化（"机器看更多"）
- 理论下限说：多目标代价 = O(目标数×面积)，不是 O(W×H)。
- 人眼加一个中央凹就牺牲视野；机器加第 N 个关注目标只多花 N×目标面积——
  **"看更多"在理论上免费（相对全帧），这是机器超越人眼的工程路径**
  （docs/138 多焦点、docs/223 多目标）。

### 方向 3：动态资源调度（把"事件数"当能效旋钮）
- 理论下限 = 事件数×成本，但**事件数不是天给的**——受转导阈值 θ 控制。
- 自适应 θ（docs/177 风暴对照 4.3×）不只是"抗噪"，是**能效旋钮**：静态场景抬阈值
  → 事件更少 → 更省；需要时降阈值 → 看更细。**能效和感知精度是同一个旋钮的两端**
  ——这是框架独有的（SNN 没有自适应 θ 的利害语义）。

### 方向 4：资格 vs 竞赛的边界（防走偏）
- 你的下限在"算法只算必要信息"（软件 + 部分硬件路线）；SNN 的下限在"脉冲电路硬件"
  （SDTrack/SpikeTrack，硬件背书）。
- 别去和 SNN 比 mW（那是它们主场）；比"同样的任务用多少计算量达成"——
  这是软件路线能赢的战场（省 95% + 利害驱动语义是 SNN 给不出的）。

## 五、诚实边界

1. px/帧是运算量代理，不是真实能耗 mW——真实能耗需硬件测量（SNN 路线做这个）。
2. 三线是复杂度分析；方向 1 的脚本（vision/transduction_sparse.py）已实现并通过安全
   运行验证（exit=0），实测数字见 §四实测结果——本文档其余数字仍是估算。
3. "事件数 = 场景变化量"是信息论立场——转导阈值改变事件数，所以事件数有控制
   自由度（方向 3），不是纯物理常数。
4. 本文档是工程方向分析，不是论文主张；论文里它是"资格证明"（框架有工程可用性），
   不是"能耗竞赛"（不碰 SNN 主场）。

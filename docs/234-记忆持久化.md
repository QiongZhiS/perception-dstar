## 一、接口设计

### 1. CLI（vision/davis_suspicious.py）

```
python vision/davis_suspicious.py --video flamingo --seed 7 --save-state
    # 跑完 7 变体后把阅历落盘到默认路径
    #   vision/out/state/flamingo_s7_gain.json（<video>_s<seed>_<corrupt>.json）
python vision/davis_suspicious.py --video flamingo --seed 7 --load-state
    # 运行前从默认路径加载阅历续跑（重启会话；等价于没重启过）
python vision/davis_suspicious.py --save-state my_state.json      # 显式路径
python vision/davis_suspicious.py --load-state my_state.json
```

- `--save-state [PATH]` / `--load-state [PATH]`：均为可选值参数（nargs="?"）。
  省略 PATH → 默认 `vision/out/state/<video>_s<seed>_<corrupt>.json`；给 PATH → 自定义。
- 状态按**稳定变体 key**（A/B/C/C2/D/E/F）存取；`--load-state` 时文件里没有的变体
  回退全新 mind，文件里多出的变体忽略（部分续跑 / 跨配置迁移都允许）。
- 加载后状态里的参数（thr_base 等）随快照生效（阅历是"当时参数下形成的"）；
  需要改参时用代码层 `DavisMind.from_state(st, **overrides)`。

### 2. 模块 API

```
ds.save_state(path, {key: DavisMind, ...}, meta={...})   # → path（自动建目录）
ds.load_state(path, cfgs={key: {构造参数}, ...})          # → {key: DavisMind}
ds.load_state(path)                                      # → {key: 原始状态 dict}
ds.default_state_path(video, seed, corrupt)              # 默认落盘位置
```

### 3. 设计决定：显式保存，不做默认自动保存

- **为什么不做默认自动保存**：A2 统计外壳每次跑 10 种子 × 7 变体，若主脚本默认落盘
  会产生大量冗余状态文件，且给"朴素运行"引入写入副作用——向后兼容的最强形态是
  **不加新旗标时行为逐字节不变**（本节所有对照都验证了这一点）。
- 阅历保存是**显式动作**（会话结束 `--save-state`），加载是**显式续跑**
  （新会话 `--load-state`）——与 docs/203 的"会话"语义对齐（遍/会话边界由使用者划）。

## 二、落盘格式

`vision/out/state/<video>_s<seed>_<corrupt>.json`：

```json
{
  "artifact": "davis_suspicious_state",
  "doc_ref": "docs/234",
  "state_version": 1,
  "saved_at": "2026-08-29T..:..:..",
  "meta": {"video": "flamingo", "seed": 7, "thr": 0.6, "corrupt": "gain",
           "seg": {"base":20,"dusk":20,"corrupt":15,"rest":25}, "n_frames": 80},
  "variants": {
    "A": {
      "task_hue": 170.0, "thr_base": 0.6, "thr_boost": 0.04, "thr_cap": 0.85,
      "relax": 0.02, "persist_for": 3, "grow": 3.0, "cap_k": 60,
      "k_band": 2.0, "wb": true, "global_thr": false, "template": false,
      "fixed_bw": null, "layered_k": false, "thr_cur": 0.6,
      "rejected": {"168.0": 5, ...},      // suspicious[hue_bin] 被拒累计（docs/205）
      "rej_total": 25,                     // 全局纪念（docs/200/203，饱和 cap_k）
      "thr_by": {"170.0": 0.04, ...},      // 类别级阈值上调量（docs/206/207）
      "hist": {"170.0": [169.1, ...]},     // bin 内观测（自适应带宽 docs/208/A1）
      "trusted": true, "consec": 0, "persist": 0,
      "g_base": [..], "n_corr": 12,        // 白平衡基线增益 + 校正帧计数
      "gate": {"mad_gate": 40.0, "alpha": 0.05, "warmup": 8, "delta_gate": 4.0,
               "d_mu": .., "prev": .., "n": 55}   // 时间门运行态（docs/199b）
    },
    "B": { ... }, "C": { ... }, "C2": { ... }, "D": { ... }, "E": { ... }, "F": { ... }
  }
}
```

- 键为色相浮点（bin 起始值），JSON 用 `str(float)` 字符串化——repr 往返精确
  （float64 无损），round-trip 验证的逐项相等即证明这一点。
- **自包含快照**：配置（机制参数）+ 阅历（suspicious/thr_by/hist/纪念）+ 运行态
  （信任状态/门/白平衡基线/校正计数）全量。缺门或 g_base 的话，重启后时间门判据
  与"相对基线增益"校正判定会从头重来——"行为等价没重启过"要求全量（见 §五 边界）。

## 五、诚实边界（什么没有持久化，为什么）

1. **观测流 / 视频帧不落盘**：状态里只有机制记忆（suspicious/thr_by/hist/纪念），
   没有帧内容。"等价于没重启过"的前提是**世界按同一 seed 重建**（build_sequence
   确定性）——这是"记忆持久化"，不是"世界持久化"。外部世界不同（不同帧/扰动）时
   阅历照常加载，但行为等价性不成立。
2. **序列构造的 RNG 状态不落盘**：`np.random.default_rng(seed)` 每会话从 seed 重建，
   会话2 会重算前缀帧（拆分对照里前缀在会话1 已跑，会话2 只跑后缀）。逐帧增量流式
   输入不在本脚本语义内。
3. **变体配置是调用方约定，不是状态裁决**：状态自包含配置快照，但加载时按当前运行
   的变体配置重建（显式传 cfg），因此支持跨配置迁移阅历（"加载 A 的阅历跑 B 配置"）。
   若配置不匹配（如 wb 状态加载进 nowb 运行），门/白平衡从零开始——不是错误，是边界。
4. **聚合状态而非事件日志**：只记被拒次数/阈值上调量/观测统计，"谁在什么帧被拒"
   不保留（docs/203 §四 4 同款边界：记忆只含被拒次数标量）。
5. **hist 无上限增长**：每帧一个 hue 观测，长期连续运行会线性膨胀；未做衰减/压缩
   ——docs/203 下一步"遗忘侧"（饱和 vs 衰减）未实现，是后续项。
6. **会话边界快照而非每帧 checkpoint**：--save-state 在跑完后写；进程崩溃时最近一次
   落盘之前的阅历丢失（A2 的 ckpt 机制管的是结果归档，不是阅历）。
7. **时间门参数与文档口径**：门参数随快照原样保存（40/4/8 为 DAVIS 重标定值，
   docs/230 已有说明）；本项不改判据，只负责原样持久化。

## 六、验证方法与安全纪律

- 全部运行走**安全模式**：`python ... *> logs\<name>.log`（PowerShell 重定向，
  子进程 stdout/stderr 不进会话），包装行只报 `exit=<code> bytes=<log大小>`；
  日志绝不读内容。
- 数字用**纯 python 正则抽取**（vision/extract_r.py：`^R_[A-Z0-9_]+=` 行回显，
  自动识别 UTF-8/UTF-16 BOM——PowerShell `*>` 会把子进程 stdout 写成 UTF-16LE）。
  本文件所有数字均为抽取值。
- 未用 read 工具读取任何输出文件（日志/JSON 产物）。
- 新增文件：
  - `vision/davis_b13_check.py` —— round-trip 验证器（RT1/RT2/RT3，R_B13_* 摘要）
  - `vision/davis_b13_compat.py` —— 向后兼容验证器（R_B13C_* 摘要）
  - `vision/extract_r.py` —— 安全模式数字抽取器
  - `vision/davis_suspicious.py`（改）—— to_state/from_state 全量化、
    save_state/load_state/default_state_path、--save-state/--load-state、
    变体稳定 key、persist_check 增落盘 round-trip
